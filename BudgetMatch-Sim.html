一、项目命名（可直接使用）

· 项目全称（中文）：基于时序电商仿真的预算约束智能选配中台

· 项目全称（英文）：BudgetMatch-Sim：Time-Series E-commerce Intelligent Matching Platform

· 项目简称（中文）：优配魔方

· 项目简称（英文/仓库名）：BudgetMatch-Sim

· Slogan：以历史价格时序数据推演虚拟电商市场，在严格预算约束下，通过自研规则与策略引擎，输出最优个性化购物选配方案。

二、产品定位与核心差异化

官方定义：本项目是一款面向预算约束场景的电商仿真决策中台，不依赖官方电商API，通过自建时序虚拟商品库与市场仿真引擎，复现商品生命周期、价格波动规律与大促规则；结合LLM意图解析与自研预算选配策略引擎，实现「自然语言需求 → 智能预算拆分 → 多约束商品组合择优 → 多方案量化输出」的全链路能力，主打中立、无营销、强约束、可仿真、可量化。

一句话（面试/简介版）
我独立设计并实现了一套基于时序仿真的预算智能选配中台，通过自建虚拟商品时序库模拟电商市场变化，结合自研预算组合策略引擎，在严格预算约束下为用户输出最优选购方案，整体采用Go微服务架构，是一套偏向电商策略与离线仿真的后端工程项目。

三、技术栈（定稿）

· 后端核心：Golang、Go-Zero、PostgreSQL、Redis

· 数据与仿真：Python（离线数据清洗、时序统计、可视化）

· 智能交互：大模型API（意图解析、结构化输出、方案润色）

· 核心自研：时序商品库建模、电商市场仿真引擎、预算分层分配策略、多约束商品组合选配规则引擎

四、核心亮点（简历/文档标准四条）

1. 自研离线电商仿真沙盘：基于历史时序数据复现商品调价、上下架、大促波动，模拟真实电商市场演进，摆脱对官方实时商品API的依赖。

2. 预算约束策略中台：自研分层选配引擎，在严格预算上限、配件兼容、品牌偏好等多维约束下，自动拆分品类配额并生成多套择优方案。

3. LLM+自研策略混合架构：大模型仅负责自然语言解析与文案输出，核心决策、数值计算、组合择优全部由自研引擎完成，规避大模型数值不精准、逻辑不可控问题。

4. 工程化微服务架构：基于Go-Zero分层解耦，实现商品中心、仿真调度中心、预算决策中心、LLM网关四大模块，对标大厂电商/广告预算调度系统设计思想。

五、落地可行性分析（摘要版）

✅ 优势：无电商API依赖、预算约束真实需求、LLM不做决策、技术栈可控。
⚠️ 核心风险：仿真可信度、冷启动商品库、用户无法直接下单、兼容性复杂度。
✅ 落地结论：先锁定「3万元以内的装机选配」作为垂直场景，MVP用Web工具验证。

六、用户与场景（MVP）

· 首选场景：装机选配（CPU/主板/显卡/内存/电源/机箱）

· 用户画像：大学生、刚工作年轻人，预算严格（5000/8000/12000元）

· 价值闭环：输出方案 + 一键复制京东/淘宝搜索词

七、核心功能规格（MVP版）

1. 时序商品库

· 包含6类核心配件

· 每个商品：基础属性 + 历史价格时序（月/周） + 上下架时间 + 大促标签

· 数据来源：公开历史价格网站 + 少量人工补充

2. 电商市场仿真引擎

· 模拟3个月价格走势

· 随机生成促销日

· 可配置是否允许缺货

3. 预算选配策略引擎（核心）

· 输入：总预算 + 偏好（Intel/AMD、性能优先等）

· 策略流程：品类预算分配 → 兼容性过滤 → 多目标优化 → 输出Top3方案

· 不依赖LLM做任何数值决策

4. LLM交互层（极轻）

· 唯一职责：自然语言 → 预算+偏好；方案 → 友好文案

· 不参与选品、价格计算、兼容性判断

九、数据与策略设计（原创性）

· 价格仿真规则：新品高价30天 → 正弦波动 ±10% → 大促 -15%

· 组合策略：强规则 + 打分排序（非ML黑盒）

· 兼容性知识库：独立维护 CPU插槽 / 主板芯片组 / 电源瓦数

十四、总结语

优配魔方不是一个“更聪明的购物助手”，而是一个“不依赖真实电商的预算决策沙盘”。它牺牲了实时性，换来了可控性、可解释性与工程自由度。

在未来，或许它可以成为真正的成为我们的”购物决策助手”
