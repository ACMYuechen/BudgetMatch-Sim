# 前端分步完善

本轮从用户端基础体验开始，沿用 React、Vite、Ant Design 与 Zustand。每一步都以现有 API 契约为依据，交付可操作页面及对应验证。

## 第一步：基础体验与账户链路

状态：已完成前端实现与模拟 API 验证，真实后端联调待完成。

本步内容：

- 浅色首页、统一导航和账户菜单，适配桌面与移动端。
- 首页填写购物需求和预算，登录后带入推荐表单；需在推荐页主动发送才会生成方案。
- 用户名/邮箱登录、注册表单校验、验证码倒计时。
- 受保护路由保存原地址，登录或注册后可继续访问；商品接口需要登录，前端路由与后端保持一致。
- 普通 HTTP 与推荐 SSE 共用会话失效处理；失败的旧请求不能清除新的登录会话。
- 按 `/api/user/info` 的 `{ user: ... }` 响应展示个人中心；移除不存在的 `/api/user/profile` 调用。
- 404、页面异常提示、页面标题与按路由加载页面。

个人中心目前只展示账户信息。用户侧后端没有资料编辑接口，因此本步不提供保存按钮。

验收记录：14 项 Chromium 浏览器测试通过，包含 360px、768px、1280px 的响应式检查；已查看桌面首页及手机注册页截图。`npm run lint` 与 `npm run build` 通过。构建仍有入口资源超过 500 kB 的提示，后续可继续做依赖拆分和体积优化。

## 第二步：商品与订单

状态：已完成前端实现与模拟 API 验证，真实订单与支付联调待完成。

- 对齐商品 `image`、`content`、`providor` 和 SKU `specs` 等真实字段。规格兼容 JSON 对象与纯文本，商品描述按纯文本展示。
- 商品搜索、分页与订单状态筛选保存在 URL；详情返回列表时恢复筛选。商品列表接口不提供价格，因此列表不展示虚构价格，也不逐个请求 SKU。
- 图片缺失或加载失败时展示占位；规格分页加载，禁用缺货/下架选项；数量范围为 `1..min(库存, 99)`。
- 增加订单确认弹窗、金额与备注、重复点击保护。同一页面内，相同 SKU、数量及备注在失败重试时复用 UUID 幂等键。
- 订单列表及详情展示真实金额、状态和商品明细；取消前要求确认，失败保留错误提示，成功重新读取后端数据。
- 明确区分支付流水状态（`0` 待支付、`1` 成功、`2` 关闭）与订单状态（`1` 待支付、`2` 已支付等）。关闭/未知支付状态不展示付款码，发起支付直接返回成功时也不展示空二维码。
- 支付查询串行轮询，每轮结束后间隔 3 秒，最多自动查询 40 次；错误或达到上限后可手动查询。关闭弹窗或离开页面会中止查询，并忽略迟到响应。
- 列表、详情及操作均补齐加载、失败重试和空状态；切换筛选时中止旧请求，避免旧结果覆盖新结果。适配桌面与手机端。

边界：幂等键当前保留在页面内存，刷新或离开页面后不保留；提交结果不明确时提示先检查“我的订单”。前端防重不能代替后端事务与幂等保障。支付接口未返回二维码到期时间，因此不再显示未经接口确认的“15 分钟有效”。本步未修改后端或发起真实订单、支付宝交易。

验收记录：新增 20 项商城浏览器测试，连同第一步的 14 项用例，共 34 项通过（`npm run test:e2e -- --workers=1`）；`npm run lint`、`npm run build` 与 `git diff --check` 通过。已查看桌面和手机端的商品详情、订单页面截图。构建仍有大于 500 kB 的资源提示，不影响本轮构建通过。

## 第三步：推荐购物流程

- 统一推荐对话样式，完善发送、取消、失败重试和历史恢复。
- 增加推荐结果到商品/下单入口，展示准确价格、预算剩余和库存提示。
- 当前订单接口只接受单个 SKU。多商品组合下单需要先明确批量订单契约，不在前端伪装成一次原子交易。

## 第四步：秒杀与管理端

- 对齐秒杀活动标题、时间及订单响应字段，完善倒计时和排队结果反馈。
- 秒杀活动/SKU 读取 RPC 目前被配置为管理员权限，普通用户真实联调需要先修正后端授权边界。
- 再实现独立的管理员页面：商品/SKU、活动、订单和 Outbox；复用现有管理 API。

## 本地开发与验证

在 `web-ui` 下执行：

```bash
npm ci
npm run dev
```

默认地址为 `http://localhost:5173`，开发服务器把 `/api` 代理到 `http://localhost:10002`。真实登录、注册与账户查询需要启动对应后端；首页及表单校验可独立查看。

```bash
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

Linux 如果缺少浏览器系统库，可按 Playwright 的提示安装 Chromium 运行依赖（`npx playwright install --with-deps chromium`）。

`tests/foundation.spec.ts` 使用真实浏览器和模拟 API 响应，覆盖首页需求传递、登录回跳、注册校验、账户信息、会话失效、移动导航、404 和多种屏幕宽度。

`tests/commerce.spec.ts` 覆盖商品字段、搜索分页、旧响应竞态、库存和下单确认、幂等重试、订单筛选/取消，以及支付成功/关闭/未知状态、失败恢复和轮询清理；并对 360px、768px、1280px 下的商品列表、商品详情、订单列表、订单详情截图及检查横向溢出。

测试会自动启动专用的 `127.0.0.1:4173` 开发服务器，不调用真实邮箱、模型、支付或数据库，也不替代真实后端联调。

截图和失败跟踪保存在 `web-ui/test-results/`，该目录不提交。
