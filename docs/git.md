# Git 提交规范

## 一、规范概述

本项目采用**社区通用 Conventional Commits** 标准，适配小团队开发。核心目的：统一提交语义、清晰迭代追溯、支持自动生成版本日志、规避混乱提交，轻量化无负担。

## 二、标准提交格式

### 模板

```Plain Text
<type>(<scope>): <description>

feat(user): 新增手机号登录接口
fix(order): 修复订单支付状态同步异常
refactor(pay): 下线废弃的旧支付逻辑
style: 统一全局代码格式
docs: 更新项目部署文档
test: 移除失效的用户模块测试用例
chore: 优化Dockerfile构建配置
```

## 三、核心提交类型（重点·唯一通用7类）

所有代码改动必须严格归类，无特殊例外：

- **feat**：新增业务功能、接口、页面、模块能力

- **fix**：修复 Bug、逻辑异常、数据错误、线上隐患

- **refactor**：代码重构、结构优化、逻辑梳理，**无新增功能、无Bug修复**（**核心：所有删除/废弃业务代码均归此类**）

- **style**：代码缩进、空格、格式调整，不修改任何业务逻辑

- **docs**：文档、注释、README、说明文本新增/修改/删除

- **test**：测试用例、测试脚本的新增、修改、删除

- **chore**：工程配置、依赖、Docker、CI/CD、构建脚本等非业务改动

## 四、高频删除场景专属归类（最常用）

- 删除业务接口/模块/旧逻辑 → **refactor**

- 删除调试代码、报错冗余代码 → **fix**

- 删除文档、注释、说明文件 → **docs**

- 删除项目依赖、配置、工程脚本 → **chore**

- 删除废弃测试用例 → **test**

- 删除多余空行、格式化清理 → **style**
