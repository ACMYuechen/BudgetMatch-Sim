## 本地开发与验证

项目位于 [web-ui](../web-ui/)，使用 React、TypeScript、Vite、Ant Design 与 Zustand。先按[首页](../README.md#本地快速开始)启动后端，再执行：

```bash
cd web-ui
npm ci
npm run dev
```

开发入口 `http://localhost:5173`，管理端 `/admin`。Vite 将 `/api/admin` 转发至 `10001`，其他 `/api` 转发至 `10002`。`make dev` 不启动 Vite；全容器前端默认端口为 8080。

在 `web-ui` 目录内验证：

```bash
npm run lint
npm run build
npm run test:e2e
```

Playwright 需要匹配版本的 Chromium 和系统依赖；首次安装可使用 `npx playwright install chromium`，缺系统库时按报错补齐，不假定任意环境都可直接运行。测试使用独立开发服务器配置，详见 [playwright.config.ts](../web-ui/playwright.config.ts)。

默认 `tests/` 主要使用模拟 API，覆盖页面交互和协议边界；它们不等于真实支付或生产联调。保留库浏览器测试在 `tests-local/`，需要显式私密配置与写入授权，不是普通 E2E 的默认入口。

## 页面能力

| 模块 | 已有能力 | 使用边界 |
| --- | --- | --- |
| 登录与基础布局 | 用户名/邮箱密码登录、邮箱验证码注册、用户信息、响应式导航 | 用户信息只读，后端尚无当前用户资料编辑接口；退出清理前端状态，不撤销 JWT |
| 商城 | 商品搜索/分页、详情/SKU、下单确认、订单查询/取消、扫码支付与查询 | 金额以分传输；单 SKU 下单，不支持一键购买整个推荐组合 |
| 推荐 | 预算/偏好输入、多轮会话、历史分页与删除、真实 SSE、取消与显式重试 | 只有 final + 成功 done + 正常 EOF 才确认结果；临时解释不是可购买方案 |
| 秒杀 | 活动/SKU、资格令牌、排队下单与订单结果轮询 | 资格令牌不是登录 JWT；暂时查不到排队订单不直接判定失败 |
| 管理端 | 商品/SKU、活动、商城订单、Outbox 运维 | 管理员范围为角色 1–99；页面权限不补齐 RPC 鉴权缺口 |

页面范围以[前端路由](../web-ui/src/router/index.tsx)为准；后端虽有验证码登录和用户管理接口，当前网页没有对应入口。推荐的真实 SKU 通过商城详情接口再次读取当前信息；Mock 商品没有真实购买入口，历史价格/库存不能直接作为下单事实。

## 需要保留的交互规则

- **身份和异步响应**：退出、切换账号或页面请求变化后，不应用旧身份/旧查询的迟到结果；管理布局重新读取用户角色。
- **重试与幂等**：推荐同轮重试保留会话/轮次标识，修改问题使用新轮次。下单的前端幂等键目前仅页面内存保存，不是跨刷新/设备的可靠恢复机制。
- **支付状态**：支付流水状态与商城订单状态枚举不同，不能互用；支付查询默认每 3 秒一次、最多 40 次，达到上限后提供手动查询，不擅自推断支付过期。
- **秒杀状态**：结果轮询默认每 7 秒一次、最多 20 次。没有完整的用户秒杀订单列表/支付链路，丢失已提交订单 ID 后不能保证自动恢复；前端数量上限不是后端业务权限。
- **管理操作**：活动预热涉及 Redis 状态重置，应明确确认；订单只提供允许的状态流转，不把“标为已支付”或退款伪装成普通运营操作；Outbox 重放不等于事件已经发送成功。
- **停止推荐**：清理临时解释与工具状态，向下游传播取消；不承诺第三方调用已停止计费，不在断流后静默重跑整轮。

完整流式契约见 [Agent 指南](AGENT.md#流式完成语义)，鉴权与错误处理边界见[权限文档](access-control.md)。

四阶段模拟测试、本地真实规则 + Mock 联调和旧生产浏览器记录的范围不同；经真实模型、商城、支付和目标发布版本的完整体验验收仍需单独执行，统一见[项目状态](status.md)。不要把历史用例数量当作当前运行结果。
